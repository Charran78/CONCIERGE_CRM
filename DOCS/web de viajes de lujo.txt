Black Tomato opera como un diseñador de viajes de lujo enfocado en la hiper-personalización, utilizando herramientas emocionales como "Feelings Engine" para captar leads y un equipo de expertos para crear itinerarios a medida. El servicio incluye una aplicación personalizada, soporte 24/7 en terreno y la exclusiva opción de alojamiento "Blink", centralizando la experiencia VIP en una plataforma que elimina la fricción para el usuario. Para más detalles sobre su metodología, visite Black Tomato.

Resumen para tu Aplicación:
Para que tu app tenga éxito en este sector, debe ser:
1.	Invisible pero Omnipresente: Interfaz limpia, pero con un conserje real a un toque de distancia.
2.	Narrativa: Cada sección debe contar una historia, no listar precios.
3.	Predictiva: Basada en datos previos para sugerir el próximo "hito" (ej. "Su hija cumple 15 años, aquí tiene 3 destinos que la deslumbrarán").
Para que un cliente de ultra-lujo (UHNWI - Ultra High Net Worth Individuals) use una aplicación, esta no debe sentirse como una herramienta de gestión, sino como un asistente personal digital. El panel VIP debe respirar exclusividad, minimalismo y, sobre todo, ahorro de tiempo.

1. La "Home" del Cliente: El Tablero de Control Emocional
No debe haber botones de "Configuración" o "Ayuda" genéricos. La pantalla principal se divide en:
•	El Próximo Hito (Hero Section): Un contador visual elegante hacia el próximo viaje. Imagen de altísima calidad del destino y un mensaje directo: "Sr. Smith, su refugio en Botsuana lo espera en 12 días".
•	Acceso Directo al Concierge: Un botón flotante o destacado con la foto de su agente asignado. No es un icono de "chat", es la cara de "James, tu experto". Al tocarlo, abre una línea directa (WhatsApp integrado o chat encriptado).
2. El Itinerario Dinámico (Storytelling UI)
Olvídate de las listas tipo calendario de Google. El itinerario debe ser una línea de tiempo visual y narrativa:
•	Capas de Información:
o	Nivel 1: Título sugerente ("Cena bajo las estrellas en el desierto").
o	Nivel 2 (Tap): Detalles logísticos (Matrícula del coche que le recoge, nombre del guía, menú pre-seleccionado).
o	Nivel 3 (Deep Dive): "El porqué": Una nota del experto explicando por qué se eligió ese viñedo específico para él.
•	Modo Offline Total: El cliente puede estar en medio del Amazonas. Todo el itinerario, mapas y documentos deben ser accesibles sin conexión.
3. La "Bóveda" de Preferencias (The Profile Vault)
Aquí es donde la app demuestra que "conoce" al cliente. Es un repositorio de datos psicográficos:
•	Preferencias de Estilo de Vida: Talla de calzado (para actividades), marcas de agua favoritas, alergias, tipo de almohada, temperatura ideal de la habitación al llegar.
•	Documentación Cifrada: Pasaportes, visas y certificados de salud accesibles en un clic (seguridad biométrica obligatoria).
•	El Historial de Momentos: Una galería de los mejores momentos de viajes pasados, reforzando la nostalgia y la lealtad a la marca.
4. Notificaciones "Ghost" (Estrategia de Comunicación)
Un cliente VIP odia el spam. Las notificaciones deben ser:
•	Transaccionales Críticas: "Su avión privado ha aterrizado y le espera en la terminal F".
•	De Deleite: "Hemos dejado una sorpresa en su suite, esperamos que la disfrute".
•	Nunca de Marketing: Nunca enviar ofertas genéricas por la app.
5. El "Buscador de Inspiración" Privado
Una sección de "Solo para ti" basada en IA y curaduría humana:
•	Si el cliente viajó a Japón y ama el minimalismo, el sistema le muestra un concepto de Blink (campamento efímero) en Groenlandia diseñado bajo esa misma estética.
•	Botón "Make it happen": Sin formularios largos. Un toque para decirle al experto: "Me gusta esto, hablemos".
Detalles Técnicos de Interfaz (Look & Feel):
•	Micro-interacciones: Transiciones suaves y lentas. La rapidez extrema se siente "barata"; la fluidez deliberada se siente lujosa.
•	Modo Oscuro Premium: Usa negros profundos (#000000) y acentos en dorado mate o el rosa característico de Black Tomato para resaltar puntos de acción.
•	Biometría: FaceID integrado en cada paso delicado para que el cliente nunca tenga que recordar una contraseña.


Para que el flujo de aprobación se sienta como un servicio de guante blanco y no como una transacción comercial, el proceso debe eliminar cualquier "fricción cognitiva". El cliente no debe sentir que está comprando, sino que está dando permiso para que la magia ocurra.
Aquí tienes el diseño del flujo "The One-Tap Proposal" para la aplicación:
1. El Aviso: La Notificación "Whisper" (Susurro)
En lugar de un email genérico, el cliente recibe una notificación push elegante y personalizada:
"Sr. Smith, hemos diseñado el concepto para su expedición a la Antártida. Está listo para su revisión en la Bóveda."
2. La Presentación: Formato "Story-First"
Al abrir la app, no aparece un presupuesto. Aparece una experiencia inmersiva:
•	Video de Apertura: Un clip de 10 segundos en alta definición (un dron sobrevolando el hielo, una mesa servida) que establece el tono emocional.
•	Narrativa Ejecutiva: Un mensaje breve de su experto asignado: "Entiendo que busca desconexión total; este itinerario evita las rutas turísticas y le sitúa en el corazón del silencio".
•	Visualización en Scroll: El cliente desliza verticalmente para ver los puntos clave (Alojamiento, Experiencia Única, Logística) con fotos a pantalla completa.
3. El Desglose: La "Transparencia Selectiva"
Los clientes de alto nivel valoran la transparencia pero odian el detalle innecesario.
•	Presupuesto Todo Incluido: Un solo número final que incluye todo (vuelos privados, propinas, tasas). No hay cargos ocultos.
•	Acordeón de Detalles: Si el cliente desea ver el desglose técnico, puede desplegarlo, pero por defecto la interfaz se mantiene limpia.
4. El "One-Tap Approval" (La firma sin fricción)
Este es el momento crítico. La app debe permitir la aprobación sin salir del entorno:
•	Botón de Acción: Un botón elegante que dice: "Aprobar itinerario y asegurar fechas".
•	Confirmación Biométrica: En lugar de firmas digitales complejas o códigos SMS, se usa FaceID o TouchID. Esto vincula legalmente la aceptación y se siente tecnológico y seguro.
•	Pasarela de Pago Invisible: Si el cliente tiene una tarjeta Black o AMEX Centurion ya vinculada en su "Bóveda", el pago del depósito se procesa en segundo plano.
5. El "Efecto Post-Aprobación" (Feedback Inmediato)
Nada más aprobar, la interfaz cambia instantáneamente para celebrar la decisión:
•	Animación de Confirmación: Un sutil efecto visual (como un confeti digital minimalista o un cambio de luz en la pantalla).
•	Mensaje de Calma: "Excelente elección, Sr. Smith. Nosotros nos encargamos de todo a partir de ahora. Su kit de bienvenida físico llegará a su oficina el martes".
6. El Estado "En Preparación"
Tras la aprobación, el viaje pasa a una sección activa donde el cliente puede ver una barra de progreso artesanal:
•	"Reservando su Villa en el glaciar..."
•	"Coordinando su encuentro con el biólogo marino..."
•	"Personalizando su menú a bordo..."
Por qué esto funciona para tu cliente de lujo:
1.	Reduce la fatiga de decisión: Presentas una solución perfecta, no una lista de opciones.
2.	Sensación de control: El cliente siente que tiene el mando, pero que el esfuerzo lo hace la agencia.
3.	Inmediatez: Elimina el intercambio de PDFs, llamadas de confirmación y esperas innecesarias.
El "Welcome Kit" es el puente entre lo digital y lo tangible. En el lujo, lo físico valida lo que se ha pagado digitalmente. Si el cliente acaba de aprobar un viaje de 50.000€ con un toque en tu app, el paquete que llega a su casa debe oler, sentirse y pesar como esa inversión.

1. El Continente: El "Black Box"
No es un sobre de mensajería. Es una caja de cartón rígido texturizado, con cierre magnético y el logo de la empresa en stamping (relieve) plateado o cobre.
•	El Aroma: Al abrir la caja, debe haber una fragancia sutil y exclusiva (marketing olfativo). Black Tomato suele usar aromas que evocan aventura o calma.

•	El Itinerario Impreso (The Lookbook): No es una guía de viaje; es un libro de arte personalizado. Tapa dura, papel de alto gramaje, con el nombre del cliente en la portada: "La Expedición de la Familia Smith". Contiene fotos del destino que parecen sacadas de National Geographic.
•	Documentación en Cuero: Una carpeta o porta-pasaportes de piel legítima (con las iniciales del cliente grabadas) que contiene las tarjetas de embarque físicas, etiquetas de equipaje de alta resistencia y una tarjeta de contacto directa con el concierge.
•	Regalos Predictivos (The "Ahead of Time" Gifts): Objetos útiles para el destino específico.

o	¿Playa? Un protector solar orgánico de edición limitada.

Un tarjetón manuscrito (no impreso) por el experto que diseñó el viaje. Debe ser personal: "Sr. Smith, recordamos cuánto disfrutó el café en su último viaje a Italia; para este viaje a Vietnam, le hemos reservado una cata privada en...".

Para que tu aplicación siga siendo relevante en este punto físico, incluye lo siguiente:
•	Códigos QR Elegantes: Dentro del libro impreso, pequeños códigos QR que, al ser escaneados por la app, abren vídeos exclusivos de los guías locales saludando al cliente o listas de reproducción de Spotify curadas para el destino.
•	El "Unboxing" en la App: La app puede enviar una notificación justo cuando el paquete es entregado: "Su kit de viaje acaba de llegar. Ábralo y prepárese para soñar".
5. El Kit de Emergencia Discreto
Una pequeña caja o sobre dentro del kit con:
•	Tarjetas de visita de los contactos locales.
•	Moneda local en billetes pequeños para propinas iniciales (un detalle de "ultra-lujo" que ahorra la molestia de buscar un cajero al aterrizar).

Tu app debe tener una sección llamada "Mi Equipaje" o "Preparativos" donde el cliente pueda ver el estado del envío de este kit y, una vez recibido, una lista de chequeo de lo que contiene.

## 1. Responsividad (Ya tienes el 90% hecho)

**Diagnóstico:** Tu código usa Tailwind CSS con clases `md:` y `lg:`. Es responsive por defecto.

**Mejoras específicas para lujo móvil:**
- **Menú Hamburguesa elegante:** En móvil, el menú de "Destinos | Inspiración" debe colapsar en un `Sheet` (shadcn/ui) que se deslice desde la derecha con opacidad.
- **Imágenes adaptativas:** Usa el componente `next/image` con `sizes` para no cargar fotos de 4K en un iPhone.
- **Scroll horizontal suave:** Para las categorías de viaje en móvil, usa `flex overflow-x-auto snap-x snap-mandatory` con `snap-start` en cada tarjeta.

```tsx
// Ejemplo de menú móvil con Sheet (shadcn)

import { Menu } from "lucide-react";

  </SheetTrigger>
  <SheetContent side="right" className="w-[250px] bg-white/95 backdrop-blur">
    {/* Enlaces de navegación aquí */}
  </SheetContent>
</Sheet>
```

## 2. Efectos y Micro-interacciones (La "Magia" del Lujo)

**Recomendación:** **Framer Motion**. Es el estándar en React para animaciones fluidas sin dependencias pesadas.

**Efectos clave para tu web:**
| Elemento | Efecto Sugerido |
| :--- | :--- |
| **Hero** | `whileInView` con opacidad y `y: -20` al hacer scroll. |
| **Tarjetas de Destino** | `whileHover={{ scale: 1.02, y: -5 }}` con transición `spring`. |
| **Portal Privado (Mockup)** | Animación de entrada `staggerChildren` para que los días del itinerario aparezcan uno tras otro. |
| **Cambio de Página** | `AnimatePresence` para transiciones suaves entre rutas en Next.js App Router. |

```bash
npm install framer-motion
```

```tsx
import { motion } from "framer-motion";

<motion.div
  initial={{ opacity: 0, y: 20 }}
  whileInView={{ opacity: 1, y: 0 }}
  viewport={{ once: true, margin: "-100px" }}
  transition={{ duration: 0.6 }}
>
  {/* Contenido */}
</motion.div>
```

## 3. Dark Mode (Elegancia Nocturna)

**Implementación sencilla con Next.js y Tailwind:**

1.  Instala `next-themes`:
    ```bash
    npm install next-themes
    ```

2.  Envuelve tu `layout.tsx` con el provider:
    ```tsx
    import { ThemeProvider } from "next-themes";

    export default function RootLayout({ children }) {
      return (
        <html lang="es" suppressHydrationWarning>
          <body>
            <ThemeProvider attribute="class" defaultTheme="system" enableSystem>
              {children}
            </ThemeProvider>
          </body>
        </html>
      );
    }
    ```

3.  Usa las variantes `dark:` en Tailwind:
    ```html
    <div className="bg-white dark:bg-slate-900 text-slate-900 dark:text-white">
      <!-- Contenido -->
    </div>
    ```

4.  **Añade un Toggle elegante:** Un botón con icono de `Sun` / `Moon` que llame a `useTheme().setTheme()`.

**Nota importante:** El mockup del Portal Privado en el HTML anterior debe respetar el dark mode. Usa `dark:bg-slate-800` en lugar de fondos blancos fijos.

## 4. Idiomas (i18n) – Llegar a Clientes Internacionales

**Opción recomendada para Next.js App Router:** `next-intl`. Es robusto, soporta Server Components y tiene excelente DX.

**Pasos básicos:**
1.  Instalación: `npm install next-intl`
2.  Configuración de `i18n.ts` con tus locales (`es`, `en`).
3.  Archivos JSON con las traducciones en `/messages`.
4.  En componentes:
    ```tsx
    import { useTranslations } from 'next-intl';
    const t = useTranslations('HomePage');
    return <h1>{t('hero.title')}</h1>;
    ```

**Estrategia de contenido:** Empieza solo con **Inglés** (mercado de lujo internacional) y **Español**. La IA puede ayudarte a traducir los primeros JSON de forma decente.

## 5. Formularios y Recopilación de Información (Conexión con tu CRM)

**El formulario de contacto es el punto de entrada a tu `CRMView`.**

**Stack recomendado:**
- **React Hook Form** + **Zod** (validación).
- **Sonner** (toast notifications elegantes).
- **Supabase** (inserción directa en tabla `contacts`).

**Ejemplo de componente de formulario:**
```tsx
'use client';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';
import { supabase } from '@/lib/supabase';
import { toast } from 'sonner';

const formSchema = z.object({
  name: z.string().min(2),
  email: z.string().email(),
  travelStyle: z.enum(['honeymoon', 'family', 'adventure']),
  message: z.string().optional(),
});

export function LeadForm({ userId }: { userId: string }) {
  const { register, handleSubmit, formState } = useForm({
    resolver: zodResolver(formSchema)
  });

  const onSubmit = async (data) => {
    const { error } = await supabase.from('contacts').insert({
      user_id: userId,
      name: data.name,
      email: data.email,
      status: 'Lead Frío',
      notes: [{ content: `Estilo: ${data.travelStyle}. ${data.message || ''}` }]
    });
    if (error) toast.error('Error al enviar');
    else toast.success('¡Gracias! Tu asesor te contactará en breve.');
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)} className="space-y-4">
      {/* Inputs con clases de lujo (bordes redondeados, focus:ring-indigo) */}
    </form>
  );
}
```

**Recopilación Avanzada (Paso a Paso):** En lugar de un formulario gigante, usa un **Stepper** (3 pasos: Datos básicos → Preferencias → Presupuesto). Reduce la fricción y aumenta la tasa de conversión.

## 6. Automatizaciones con n8n y Webhooks (El "Cerebro" Oculto)

Aquí es donde tu herramienta se convierte en un **ecosistema inteligente**.

**Flujo propuesto:**

1.  **Disparador:** Un nuevo `contact` es creado en Supabase con `status = 'Lead Frío'`.
2.  **Webhook en Supabase:** Usa **Database Webhooks** (nativo de Supabase) para enviar una petición POST a tu instancia de **n8n** (self-hosted o cloud).
3.  **Workflow en n8n:**
    - Recibe los datos del lead.
    - **Nodo Supabase:** Busca el email del asesor asignado.
    - **Nodo Telegram / WhatsApp:** Envía un mensaje al asesor: *"🚀 Nuevo lead: María Pérez quiere luna de miel en Maldivas. Revisa el CRM."*
    - **Nodo Google Sheets:** (Opcional) Guarda un backup en una hoja de cálculo.
    - **Nodo HTTP Request:** Llama a tu propio endpoint de Next.js para crear una tarea inicial en el CRM.

**¿Por qué n8n y no solo lógica en Next.js?** Porque las automatizaciones de viajes de lujo cambian constantemente. n8n permite que el **propio asesor** (sin saber programar) modifique el flujo: *"Ahora quiero que cuando un lead escriba 'aniversario' en el mensaje, se envíe un email al hotel automáticamente"*.

**Implementación técnica del Webhook en Supabase:**
```sql
-- Habilitar extensión pg_net (si usas self-hosted) o usar Supabase Dashboard -> Database -> Webhooks
-- Configurar webhook apuntando a https://tu-n8n.com/webhook/lead-creado
```

## 7. OAuth (Login Social para Clientes y Asesores)

**Esto ya lo tienes prácticamente resuelto con Supabase Auth.**

**Para los Asesores (Acceso al CRM):**
- Habilita **Google OAuth** en Supabase Auth settings.
- En tu página `/login`, usa `supabase.auth.signInWithOAuth({ provider: 'google' })`.
- **Row Level Security (RLS):** Asegúrate de que las políticas de `contacts` solo permitan leer/escribir si `auth.uid() = user_id`.

**Para los Clientes (Portal Privado):**
- **No uses OAuth.** El lujo odia las contraseñas. Usa **Magic Link** o **Token único** (como ya haces en `PortalPage`). Si quieres añadir autenticación para que puedan volver, usa `supabase.auth.signInWithOtp({ email })`. Recibirán un enlace mágico en su correo.

## 9. Integración con Bot de Telegram y WhatsApp Business

Este es el **canal de comunicación premium** que diferencia a una agencia de lujo.

### A. Bot de Telegram (Para el Asesor - Interno)

**Objetivo:** El asesor recibe alertas y puede responder rápido sin abrir el CRM.

**Implementación:**
1.  Crea un bot con **@BotFather**.
2.  Guarda el `TELEGRAM_BOT_TOKEN` en tus variables de entorno.
3.  Usa la librería `grammy` o `node-telegram-bot-api`.
4.  **Caso de uso en tu CRM:**
    - Cuando un cliente ve el portal 3 veces en un día, el webhook de n8n llama a un endpoint que envía un mensaje al chat privado del asesor: *"⚠️ Javier ha abierto el portal 3 veces hoy. Quizá tiene dudas sobre el vuelo."*

```ts
// Ejemplo mínimo con grammy
import { Bot } from "grammy";
const bot = new Bot(process.env.TELEGRAM_BOT_TOKEN!);
bot.api.sendMessage(CHAT_ID, "Nuevo lead en el CRM");
```

### B. WhatsApp Business API (Para el Cliente)

**Opciones realistas:**
| Opción | Coste | Complejidad | Ideal para |
| :--- | :--- | :--- | :--- |
| **Meta Cloud API** | ~0.05€/conversación | Alta (verificación de negocio) | Escala y profesionalidad |
| **Twilio** | Similar | Media | MVP rápido sin verificación de Facebook |
| **Wassenger / Chat-API** | Bajo (no oficial) | Baja | Pruebas iniciales (riesgo de bloqueo) |

**Flujo de lujo con WhatsApp:**
1.  Cliente rellena formulario web.
2.  Webhook de n8n envía un mensaje de **plantilla aprobada** por WhatsApp: *"Estimado [Nombre], soy Clara de [Agencia]. He recibido tu solicitud. ¿Prefieres que te llame mañana a las 10:00 o a las 16:00?"*
3.  El cliente responde "10:00".
4.  El CRM de la agencia recibe la respuesta y agenda la tarea.

**Consejo para empezar:** Usa **Twilio** para WhatsApp. Tienen un sandbox gratuito para pruebas. Integrarlo con n8n es directo usando el nodo "Twilio".

### 1. El Problema de Mantener Dos Mundos (HTML Puro vs. React)

Si haces la landing en HTML plano y el CRM/Portal en React, te enfrentarás a esto en 3 meses:

| Tarea Cotidiana | Mundo HTML Puro | Mundo React |
| :--- | :--- | :--- |
| **Cambiar el logo o el color corporativo** | Editar 15 archivos `.html` a mano. | Editar 1 componente `Layout` o `globals.css`. |
| **Añadir una nueva página de destino** (ej: "Luna de Miel en Enero") | Copiar y pegar el header/footer, romper algún estilo, rezar. | Crear `app/estilos/luna-de-miel/enero/page.tsx`, importar `<Layout>`. Listo. |

| **Activar Analytics (tracking de conversiones)** | Añadir scripts manualmente en cada HTML. | Layout global o `next/script`. Una sola vez. |

**Conclusión:** Mantener el HTML que te pasé es un **MVP para validar el diseño visual**, pero es una **deuda técnica asesina** si planeas escalar a las 40+ páginas de contenido que listaste de Black Tomato.

### 2. ¿Por qué React y no otro Framework (Vue, Svelte, Astro)?

Ya tienes **el 70% del cerebro de la operación programado en React** (`CRMView`, `PortalPage`, `AIModal`). Usar otro framework para la web pública sería un suicidio productivo.

- **Next.js (App Router):** Es el estándar para SaaS. Te da SEO (vital para competir con Black Tomato), Server Components (carga rápida en móviles), y API Routes para conectar con n8n sin montar otro servidor.
- **React + TypeScript:** El tipado estricto te salvará la vida cuando el proyecto crezca y tengas que refactorizar el `Contact` type.

### 3. ¿Debo aplicar SOLID y TDD (Tests) desde el inicio?

Aquí va una dosis de realismo mezclada con ambición sana:

- **SÍ a SOLID en la lógica de negocio.** Especialmente la **S (Single Responsibility)** y la **D (Dependency Inversion)** .
    - *Ejemplo:* Tu `CRMView` actual está bien, pero el `handleBulkDelete` y la lógica de `PapaParse` deberían estar en un **Custom Hook** (`useContacts`) o un **Servicio** (`contactService.ts`). Esto es **SOLID** y facilita el testing.
- **SÍ a los Tests de Integración (CRUD).** El 80% de los bugs en un SaaS vienen de: *"El formulario guardó mal el estado"* o *"El webhook no se disparó"*.
    - **Testing Library + Vitest:** Escribe 1 test para el flujo crítico: *Usuario rellena formulario -> Se crea lead en Supabase -> Se muestra en la tabla*. Ese test es tu red de seguridad.
- **NO te obsesiones con 100% de cobertura en la UI.** Los tests de renderizado de píxeles son frágiles. Testea **comportamiento**, no CSS.

### El "Momento de la Verdad": Conectar el Formulario al CRM

Una vez tengas el esqueleto visual, el hito que convierte tu web en un **SaaS** es este:

1.  El formulario de "Solicitar Propuesta" envía datos a una **Server Action** (`app/actions/leadActions.ts`).
2.  La Server Action inserta en la tabla `contacts` de Supabase.
3.  El `CRMView` (que ya tienes programado) **muestra el lead al instante**.

**Código de ejemplo para la magia (Server Action):**
```ts
// app/actions/leadActions.ts
'use server';

import { createClient } from '@/lib/supabase/server';
import { revalidatePath } from 'next/cache';

export async function createLead(formData: FormData) {
  const supabase = createClient();
  
  const { error } = await supabase.from('contacts').insert({
    name: formData.get('name'),
    email: formData.get('email'),
    status: 'Lead Frío',
    user_id: process.env.DEFAULT_AGENT_ID! // O el ID del usuario logueado
  });

  if (error) return { success: false, error: error.message };
  
  revalidatePath('/dashboard'); // Actualiza el CRM si está abierto
  return { success: true };
}
```
